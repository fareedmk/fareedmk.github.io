# Clover capability audit

Audit date: **2026-10-17**. Scope: one U.S. merchant, USD, online pickup.

## Evidence and release decision

**Live integration is blocked.** Official documentation URLs were identified through search, but direct retrieval of `docs.clover.com` failed with DNS resolution errors. Direct attempts against the atomic-order guide, existing-order payment reference, and webhook guide also failed. Search summaries were inconsistent about cross-API payment association, OAuth `state`, and webhook authentication. They are **not** adequate evidence for an implementation contract.

No merchant credentials, sandbox account, payment tests, physical devices, or production acceptance evidence were available. There is **no verified sandbox integration in this delivery**. Mock behavior is an application contract, not a representation that Clover provides the same semantics.

Classification:
- **V — Verified and supported:** directly established by readable official documentation and applicable evidence. No live feature qualifies in this audit.
- **C — Supported with conditions:** readable official contract established, but merchant/device conditions remain. No live feature is promoted to this classification based only on search summaries.
- **A — App-managed rather than Clover-native:** implemented or planned locally; not evidence of a Clover capability.
- **U — Unsupported or not yet verified:** blocked pending evidence; this does **not** assert Clover cannot support it.

In the table, **S/P unknown** means sandbox and production availability, account eligibility, regional host, and exact schemas have not been verified. **Permission unknown** means an exact OAuth scope/permission string must not be inferred. Never request broad permissions as a substitute for verification.

## Field ownership and verification protocol

Future Clover-owned fields: item/provider IDs, base prices, modifier identities/prices, tax configuration. App-owned: layout, merchant-authored marketing/allergen text, images where unavailable, online visibility, promotional rules, pickup capacity/hours. Mock seeds are not a Clover import.

Required import implementation remains blocked: pagination schemas, rate-limit/retry contract, ownership-preserving upserts, archived records, cursor persistence, scheduled reconciliation, supported webhook refreshes, last-success time, and failure alerts. The current “sync” endpoint explicitly reports a mock catalog read; it is not a live sync.

Before selecting the live payment path, obtain readable official schemas and record merchant sandbox evidence for: current cart calculation → exactly one intended Clover order → tokenized payment → authoritative payment read matching order/currency/amount → target intake interface → full and partial refund. Reject any path that cannot preserve financially relevant item/modifier/discount/tax/tip records. Record international card policy independently.

For stock, test and record each transition independently: unpaid creation, successful payment, declined payment, cancellation before/after payment, partial/full refund, and optional restock. Until observed, there is **no claim of inventory decrement or restoration**.

For webhooks, verify the exact documented setup and per-event authentication mechanism before enabling the route; then validate merchant association, persist/deduplicate inbox events, acknowledge quickly, and re-fetch authoritative records. Do not treat browser redirects or unverified callbacks as proof of money movement.
